Corrected exact iocl_craq theory, fanout 4

Model:
    clean read reaches execute-ready state at 100ms
    dirty read reaches execute-ready state at 300ms (the speculative VersionRequest overlaps coordination, so dirty reads line up with writes rather than adding another post-CR RTT)
    write reaches execute-ready state at 300ms
    each of the 3 adjacent dependency hops collapses to 0ms with probability 1/10, otherwise costs 100ms
    if E_i is the execute time of op i, then
        E_0 = arrival_0
        E_i = max(arrival_i, E_(i-1) + hop_i)
    client-observed latency = E_3 + 100ms

This gives an exact support of 200ms to 700ms.

100% reads,
    fanout 4,
        iocl_craq
            all 4 ops are clean reads, so:
                each op reaches MIDDLE at 100ms
                each of the 3 dependency hops costs either 0ms (collapse) or 100ms (no collapse)
                client-observed latency = 200ms + 100ms * (# of non-collapsed hops)

            Since each hop collapses with probability 1/10:
                P(3 collapses) = 0.1^3 = 0.1%
                P(2 collapses) = 3 * 0.1^2 * 0.9 = 2.7%
                P(1 collapse)  = 3 * 0.1 * 0.9^2 = 24.3%
                P(0 collapses) = 0.9^3 = 72.9%

            Bucket percentages:
                200ms: 0.10%
                300ms: 2.70%
                400ms: 24.30%
                500ms: 72.90%

            CDF:
                <=200ms: 0.10%
                <=300ms: 2.80%
                <=400ms: 27.10%
                <=500ms: 100.00%

        Notes:
            this is the pure clean-read staircase
            there should be no intrinsic mass above 500ms in the isolated-batch model
